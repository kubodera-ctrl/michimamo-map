# 開発22 公開基盤・広域クラスタ

## 対応
- クラスタを件数による緑/黄から施設種別の固定色へ変更。警察署・交番・駐在所は青、AEDは赤、将来の子供110番は緑。追加調整：白枠・影・種別ラベルを除去、半透明のぼかした色と正確な件数のみ表示。40/46/52pxに縮小。カテゴリ分離、表示フィルター、ズーム16で個別化を維持。
- 開発21の活動履歴・否認理由・再投稿導線は実装済み。作り直していない。
- AED投稿のINSERT権限を証拠入力列だけに限定。審査状態、審査者、メモ、日時、不正フラグはサーバー管理。本人の非公開領域に写真が存在することを必須化。
- 一般写真の匿名アップロードを廃止。ログイン・有効アカウント・本人フォルダーを必須化、10MB/JPEG・PNG・WebP制限。公開済みURLは維持。
- 一般投稿の写真もJPEG再生成でEXIF削除。個人情報が写らないことの確認欄を追加。実装されていないAI検閲・モザイク処理を実行中とする表示を訂正。自動顔/ナンバーマスキングは未実装と明記。
- 写真差替えの非同期競合、変換失敗時の古い写真の誤送信、閉じたフォームへの変換結果反映を防止。
- ログイン専用RPC8本とトリガー2本から不要な匿名実行権限を削除。公開地図・出典・ランキングのRPC3本は維持。

## 開発22 続き：異議申立て・退会実処理
- マイページの否認AED・非表示投稿から理由を送信。本人所有と対象状態をDB検証、1投稿1回・24時間3件まで。本人だけに履歴を公開。
- 管理者は理由を回答し判断維持／AED再審査／投稿復元を選択。AED再審査は自動承認・ポイント付与をしない。投稿復元は通報数をリセットし、元の数と操作を監査記録に保存（投票レコードは維持）。
- 管理者が申請番号を入力して退会を実行。開始時に停止・新規書込防止、写真をStorage APIで削除、投稿/ポイント/プロフィールを削除、Auth Admin APIで認証アカウントを削除してから完了。バッチ途中や障害時は同じ申請から再開。
- 確認済みAEDの施設情報は投稿者への参照を外して保持。申請理由・ユーザーIDは完了後消去。管理者本人/管理者登録のある対象、所有権不明の旧写真は自動削除を拒否。
- Edge Function `account-deletion` v1を配置。ゲートウェイverify_jwt=falseだが、関数内でAuth getUserによるJWT検証と既存admin_validateの管理者権限＋パスワード検証を必須化。service_roleはサーバー環境変数だけで使用。許可Originは本番のみ。
- DB migrations: `20260916040529_dev22_appeals`、`20260916040532_dev22_account_deletion`（生成版番号）。
- `tests/dev22_appeals_deletion_transaction.sql`：本人受付、重複/他人/非管理者/クライアント清掃拒否、削除中書込防止、写真残存・Auth残存時の完了拒否、再開、匿名化済み完了証跡、古いJWTの無効判定を確認しROLLBACK。実データの削除は一切行っていない。
- `tests/account_deletion_worker.test.mjs` 6件：Storage→DB→Authの順序、写真/Auth障害、Auth削除済み再開、バッチ制限、完了済みの再実行。
- 写真/周辺候補の競合テスト6件、AED既存5件、ポップアップ回帰、HTML内JS構文も確認。
- 残り：実機E2E、画像の自動マスキング・審査、クイズのサーバー採点。次の既定機能は近くの安全スポット。
