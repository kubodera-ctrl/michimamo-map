# まちまも｜ニュース選定・保持ポリシー CURRENT 2026-09-27

## 1. 保持期間

- ユーザー向けMAP/ニュース候補のactive対象は原則「直近60日」。
- 60日を超えた未使用ニュース候補はactive表示・候補選定から外す。
- 90日以上の古いニュースをMAP/候補へ残し続けない。
- ただし実際に動画生成・承認・公開・訂正対応へ使ったニュースは、監査・二重投稿防止・訂正追従のため source_event_id / source_hash / revision / publication / audit の最小メタデータを保持する。古いニュース本文やMAP pinを残すこととは分離する。

## 2. 選定原則

まちまもで重要なのは『地域の人が、今その地域で気をつける意味があるか』。全国ニュース性そのものより、地域性・対人安全・子ども/弱者保護・再発可能性・生活への影響を優先する。

### 優先取得・優先表示

- 痴漢、つきまとい、声かけ、公然わいせつ、盗撮、不審者、暴行、傷害、強盗、脅迫などの対人事案
- 誘拐、連れ去り、子どもの行方不明、迷子、子ども捜索、保護要請
- 女性・子ども・高齢者などを対象にした地域安全情報
- 地域内で発生・検挙された詐欺、特殊詐欺、窃盗、万引きグループ等
- 当該地域を拠点・活動拠点とする組織的犯罪。被害が全国に及んでも地域との具体的接点があれば対象
- 地域の住民行動に影響する重大事故、火災、刃物、逃走、危険物、避難・通行規制等
- 出入国管理法等の違反による逮捕情報は、地域との具体的接点があり公的機関の一次情報で確認できるもの。国籍そのものを見出しの煽り要素にしない。

### 条件付き

- 自殺・転落・死亡事案：SNSの話題性だけでは優先しない。交通停止、立入規制、救助、学校・地域への影響等の公共安全上の意味がある場合に限り候補。方法や詳細地点を過度に強調せず、動機を推測しない。
- 空港・港湾・税関の摘発：地域住民の安全や周辺運用への具体的影響がある場合のみ。単なる入国時の違法物発見・税関摘発は通常除外。
- 海外逮捕：地域との具体的な被害・拠点・捜査上の接点が確認できる場合のみ。
- 全国事件：地域拠点、地域被害、地域での逮捕・捜索など明確なローカル接点がある場合のみ。

### 原則除外

- 海外だけで完結する詐欺グループ逮捕など、地域との具体的接点がないもの
- 空港での一般的な税関摘発・違法物発見だけの案件
- 防犯キャンペーン、啓発イベント、採用、表敬訪問、統計だけの広報
- 芸能・スポーツ・政治等で地域安全と直接関係しないもの
- 古い事件の再掲だけで現在の地域安全上の意味がないもの
- 権利・出典・事実確認ができないもの

## 3. 地域性判定

次のいずれかを満たす場合、地域接点ありと判定できる候補とする。

- 発生地が市区町村まで特定されている
- 逮捕・捜索・保護・発見地が市区町村まで特定されている
- 犯罪グループ等の拠点が地域内と一次情報で確認できる
- 被害対象・捜索対象・公共交通/道路/施設への影響が地域内にある

単に記事タイトルに地域名があるだけでは十分としない。

## 4. source/facts/rights gate

- 一次sourceを優先。警視庁等Open DATAはsource_event_idと訂正追従を保持する。
- verifiedFactsにない事実を補完しない。
- source URL / source id / occurred_at / published_at / prefecture / municipality / category / facts / rights / source_hash / correction_statusを保持する。
- LEGACY_UNVERIFIEDは候補閲覧のみ。生成・公開不可。
- REVIEW_RIGHTS/BLOCKEDは自動公開不可。

## 5. MAPとSNSの分離

- MAPの保持・表示対象と、SNS Production候補を同一ルールにしない。
- MAPは直近60日を原則とし、viewport/地域単位取得へ移行する。
- SNSは60日以内でも『今伝える価値』で選定する。件数不足を古いニュースや無関係ニュースで埋めない。

## 6. ユーザー例の採用判断

- 海外で詐欺グループ逮捕 → 原則除外
- 新宿区で詐欺グループ逮捕 → 対象
- 新宿区を拠点とする全国的万引きグループ → 対象
- 羽田空港で入国時に違法物発見 → 原則除外
- 飛び降り自殺 → 条件付き。SNS目的だけで優先しない
- 痴漢 / つきまとい / 誘拐 / 迷子 / 子ども捜索 → 優先
- 出入国管理法違反等の逮捕 → 地域接点・一次情報確認を条件に対象

## 7. 実装順

1. 東京は警視庁Open DATA直接adapterを作る。
2. candidate layerで60日retentionとcategory/locality classifierを適用。
3. source/facts/rightsを満たす候補だけ管理画面へPUBLISHABLE/TEST_OKとして出す。
4. 旧spots.officialはLEGACY_UNVERIFIEDとして分離。
5. MAPをviewport/地域単位取得へ最適化してから件数を増やす。
6. 東京安定後、Source_Master順で他道府県へ拡張する。
