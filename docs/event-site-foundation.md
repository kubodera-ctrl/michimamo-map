# まちまもイベント — 第二軸 基盤仕様

更新: 2026-09-18

## 目的

「まちまもイベント」は、全国のイベントを探す独立Webサイトとして公開し、まちまもMAPの「今日のまち」と同じ共通イベントDBを利用する。

導線は以下を基本とする。

Google検索 → まちまもイベント → イベント詳細 → 周辺の安全情報 → まちまもMAP

## 守る原則

- 既存のまちまもMAP本体を壊さない。イベントサイトは別フロントエンドとして分離する。
- Supabaseは既存プロジェクトを共用し、イベントDBだけを追加する。
- 公式API、オープンデータ、RSS、主催者提供、利用許諾を確認できる情報を優先する。
- 無断スクレイピングを前提にしない。
- AIはカテゴリ・タグ候補などの補助に限定し、日時、住所、料金、予約条件などの事実を推測しない。
- イベント画像は利用条件が確認できたものだけ表示する。条件不明はブランド用フォールバック画像・背景を使う。
- 公開情報には出典、取得・更新時刻、公式URLを保持する。
- 同一イベントはタイトルだけでなく日時、会場、主催者、URLを組み合わせて重複判定する。
- 公開状態と確認状態を分離し、期限切れ・訂正・非公開へ戻せる設計にする。

## 初期フロントエンド構成

既存MAPは巨大な単一HTMLを中心に稼働しているため、イベントサイトを同じファイルへ混在させない。

- repo: michimamo-map
- folder: event-site/
- frontend: Next.js App Router
- deploy: Vercelの別Projectとして event-site/ をRoot Directoryに指定
- backend: 既存Supabase
- public access: 公開RPCのみ
- write/import: service role / 管理者系のみ

これによりMAPのβ安定性を保ちながら、イベントサイトだけSEO向けSSR/SSG構成へ進化できる。

## DB公開境界

クライアントから events / regional_sources / event_source_records を直接読ませない。
公開は以下のRPCに限定する。

- search_public_events
- get_public_event
- get_public_event_sitemap

書き込みは一般クライアントへ許可しない。E4で主催者投稿専用テーブルと審査RPCを追加する。

## 最初の完成条件

1. DB migrationがロールバック可能
2. イベント0件でもサイトが正常表示
3. 公開済み・確認済みイベントだけ検索結果へ出る
4. 出典がないイベントを公開できない
5. 画像条件不明なら画像を表示しない
6. 今日・明日・今週末・地域検索が機能
7. 詳細ページに公式URL・出典・最終確認時刻を表示
8. Event JSON-LDが事実データだけで生成
9. MAP本体の既存ファイルを変更せず独立デプロイ可能
10. 全国展開前に限定地域で重複・期限・削除を検証
