# まちイベ — 第二軸 基盤仕様

更新: 2026-09-18

## 目的

「まちイベ」は、全国のイベントを探す独立Webサイトとして公開し、まちまもMAPの「今日のまち」と同じ共通イベントDBを利用する。

導線は以下を基本とする。

Google検索 → まちイベ → イベント詳細 → 周辺の安全情報 → まちまもMAP

## 守る原則

- 既存のまちまもMAP本体を壊さない。イベントサイトは別フロントエンドとして分離する。
- Supabaseは既存プロジェクトを共用し、イベントDBだけを追加する。
- 公式API、オープンデータ、RSS、主催者提供、利用許諾を確認できる情報を優先する。
- 無断スクレイピングを前提にしない。
- AIはカテゴリ・タグ候補などの補助に限定し、日時、住所、料金、予約条件などの事実を推測しない。
- イベント画像は利用条件が確認できたものだけ表示する。条件不明はブランド用フォールバック画像・背景を使う。
- 公開情報には出典、取得・更新時刻、公式URLを保持する。
- 同一イベントはタイトルだけでなく日時、会場、主催者、URLを組み合わせて重複判定する。
- 公開状態と確認状態を分離し、期限切れ・訂正・非公開へ戻せる設計にする。

## 初期フロントエンド構成

既存MAPは巨大な単一HTMLを中心に稼働しているため、イベントサイトを同じファイルへ混在させない。

- repo: michimamo-map
- folder: event-site/
- frontend: Next.js App Router
- deploy: Vercelの別Projectとして event-site/ をRoot Directoryに指定
- backend: 既存Supabase
- public access: 公開RPCのみ
- write/import: service role / 管理者系のみ

これによりMAPのβ安定性を保ちながら、イベントサイトだけSEO向けSSR/SSG構成へ進化できる。

## DB公開境界

クライアントから events / regional_sources / event_source_records を直接読ませない。
公開は以下のRPCに限定する。

- search_public_events
- get_public_event
- get_public_event_sitemap

書き込みは一般クライアントへ許可しない。E4で主催者投稿専用テーブルと審査RPCを追加する。

## 最初の完成条件

1. DB migrationがロールバック可能
2. イベント0件でもサイトが正常表示
3. 公開済み・確認済みイベントだけ検索結果へ出る
4. 出典がないイベントを公開できない
5. 画像条件不明なら画像を表示しない
6. 今日・明日・今週末・地域検索が機能
7. 詳細ページに公式URL・出典・最終確認時刻を表示
8. Event JSON-LDが事実データだけで生成
9. MAP本体の既存ファイルを変更せず独立デプロイ可能
10. 全国展開前に限定地域で重複・期限・削除を検証


## 検索品質 v2（2026-09-18追加）

イベント件数が増えるほど「検索に出ること」より「不要なものを消せること」が重要になるため、検索機能を以下へ拡張する。

### 除外ワード
- 任意の除外ワードを複数指定可能。
- 「、」またはカンマ区切り。
- タイトルだけでなく、説明、会場、自治体、主催者、料金文も対象にする。
- アフタヌーンティー、ビュッフェ、ディナー等を利用者自身が除外できる。
- 子ども向け検索だからという理由だけで特定ワードを自動除外しない。誤除外を避け、利用者が明示的に指定する。

### 開催期間
- 1日
- 2〜4日
- 5〜10日
- 11〜30日
- 31日以上

長期イベントが繰り返し上位を占有しないよう、標準の「おすすめ」では同じ週の中で新規開始・短期開催を優先する。
完全に隠すのではなく、利用者が「開催日順」「短期順」「新着順」へ切り替えられる。

### 子ども向け精度
年齢タグとは別に、以下の audience_intent を持つ。
- child_centered: 子どもが主役
- family_friendly: 親子で楽しめる
- general: 一般
- adult_oriented: 大人向け

AIが推測しただけでは検索条件に使わず、確認済み分類だけを「子どもが主役」「大人向けを除く」に利用する。

### 障害者向け・配慮情報
「障害者向け」という一括タグだけではなく、出典で確認できた具体的な配慮を保持する。
- 車いす対応
- バリアフリートイレ
- 優先・障害者用駐車場
- 介助者・同伴者対応
- 手話
- 字幕・文字情報
- 音声案内・音声解説
- 感覚過敏への配慮
- 補助犬
- 障害者手帳等の割引

不明な配慮をAIで補完しない。公式・主催者情報にないものは「不明」のまま扱う。

### 長期・不定期イベント
start_date/end_dateだけでは「1か月間の毎週土日」のような開催を正しく表現できないため、event_occurrencesで実開催日を別管理する。
検索結果の長期占有対策には表示期間（start〜end）を使い、カレンダーや詳細表示には実開催日を使える構造にする。

### リピーター向け次期機能
- 閲覧済みイベントを薄く表示／非表示
- 「このイベントを今後表示しない」
- 保存した検索条件
- 前回訪問後に追加されたイベントだけ表示
- 除外ワードの端末保存

これらはログイン必須にせず、まず端末保存で利用できる設計を優先する。


## 行動導線 v3：探す → 決める → 当日 → 遊んだ後

イベントサイトを「探して終わる」サイトにせず、1日の行動全体を支える。

### 決める
- 「行きたい」ブックマーク。まず端末保存、後にLINE認証時クラウド同期。
- 行きたい一覧。
- Googleカレンダー追加。
- iPhone / Apple Calendar / Outlook等へ .ics 追加。
- Google Maps / Apple Maps で会場までナビ。
- 駐車場検索。一般検索は地図、予約ASPはPR枠として通常情報と分離。
- 共有。

### 当日
イベント地点をキーに、まちまもMAPへ直接送る。
- 今日のWBGT
- 近くのAED
- 近くの交番
- 周辺道路の安全情報
- 地域ニュース
- まちまもMAP

リアルタイム渋滞を未接続の段階で「交通状況」と断定しない。対応データ源が確定するまでは「周辺道路の安全情報」と表現する。

### リピーター
- 閲覧済みを薄く表示 / 非表示
- 「今後表示しない」
- 保存検索
- 前回訪問後の新着だけ
- 除外ワードの端末保存
- 行きたいイベントの地図表示
- 複数の行きたいイベントから「おでかけプラン」へ発展

## 遊んだ後の「ごはん」検索

イベント終了後に周辺の飲食店を探せる導線をイベント詳細へ常設する。

一般的な条件:
- 距離
- ジャンル
- ランチ / ディナー
- 予算
- 個室
- 禁煙
- 駐車場
- バリアフリー
- 子ども連れ可
- キッズメニュー
- ベビーチェア
- ベビーカー
- 離乳食持込等

まちまも独自の重要条件:
- 0〜2歳無料
- 未就学無料
- 未就学半額
- 小学生無料
- 小学生半額
- 子ども料金あり
- 障害者手帳等の割引
- 介助者 / 同伴者条件

「未就学無料」「未就学半額」は単純booleanにしない。ホテルビュッフェ等では曜日、時間帯、人数条件、保護者同伴、特定プラン限定などの条件があるため、年齢層・食事区分・割引方式・条件文・有効期間・出典URL・確認日時を構造化して保存する。

### 飲食店データの方針
- 一般店舗検索は外部の許諾済みAPI / 公式情報を基礎にする。
- 子ども料金等の不足情報は「まちまも独自補助データ」として別レイヤーで持つ。
- 外部APIに無い料金条件をAIが推測して埋めない。
- 公式メニュー、店舗公式、施設公式、店舗提供、許諾済み情報で確認できたものだけ「確認済み」にする。
- 条件が古くなりやすいので最終確認日を表示する。
- API提供元の規約に応じて保存可否を分け、必要ならライブ検索結果に独自補助情報だけ重ねる。
